# 猫源详情缺少作品 ID 的兼容

2026-10-23。

## 问题

「盘」玩偶的“空枪”搜索结果携带作品 ID 133081，详情返回单条 list，含名称、封面、简介及播放线路，但未返回 vod_id。通用列表解析器要求 ID 和名称均有效，将其丢弃，详情客户端返回 null，页面因此显示“该作品已不可用”。

手机日志中详情 HTTP 200、耗时 4727 毫秒、响应 2865 字符，仅能确认请求成功，未记录响应正文。独立桌面环境运行此前校验过的同一份来源脚本，复现了缺少 vod_id 的响应及实际客户端返回 null。临时在内存补入请求 ID 后，通用解析器读出 5 条线路、8 个播放条目。

## 修复边界

修复只在 CatNodeClient.detail 的来源适配边界执行，调用 bindDetailIdentity 后再交给原解析器：

- 请求 ID 非空，list 原始长度恰好为 1，条目是对象，且 vod_id 未提供、为 null 或空白字符串时，沿用请求 ID。
- 显式返回不同 ID、无效 ID 类型、多条条目、空列表或非对象条目不猜测身份，不取第一条兜底。
- 名称、列表结构和来源错误码继续由通用解析器验证；首页、分类、搜索列表保持严格校验。
- 订阅目录命名空间、跨目录详情及播放线路、历史记录的 ID 恢复逻辑保持原样，不按目录名称特判。

这解决的是缺少身份字段造成的详情误判，不保证来源的网盘登录、分享链接和实际播放链路可用。

## 验证

259 项相关回归测试通过，其中客户端 31 项。新增覆盖缺失/null/空白 ID、特殊字符 ID、数字 0、明确不同 ID、错误类型、多条与空详情、空标题、来源错误、字符串包装响应、订阅命名空间、跨目录播放参数及历史 ID。

实际来源复核和应用编译、签名、产物校验记录位于 tmp/detail-id-fix。来源脚本只在独立临时目录权限内运行，桌面 Permission Model 不支持 fsync 的差异仅由临时测试进程跳过 flush，应用运行代码未作此替换。未自动安装或调试设备，未尝试实际媒体播放。
