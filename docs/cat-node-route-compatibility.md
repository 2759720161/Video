# 猫源接口路径兼容

2026-10-23，LeeCatPaw 订阅切换网络并成功保存后，目录「盘」TG搜提示：

`HTTP 404: Route POST:/spider/tgchannel/init not found`

项目此前从 `/config` 的 `api: /spider/tgchannel/3` 中提取作品来源标识 `tgchannel`，请求时直接拼接 `/spider/tgchannel/<method>`，丢失了接口路径中的类型段 `/3`。这个包将方法注册在完整路径下，因此初始化就失败，与此前下载校验文件时的网络连接失败是两个阶段的问题。

现在目录解析保留经过校验的本地相对 API 路径。初始化、首页、分类、搜索、详情和播放共用该路径；作品标识仍使用原来的来源 key，不改变已有播放记录。运行环境重启后重新读取目录并协商路径，不沿用上一个运行环境的结果。

项目以多源适配为目标。带类型段 `/spider/<key>/<type>` 和无类型段 `/spider/<key>` 是两种接口形式，不代表源的新旧。优先使用目录声明的 API；仅当初始化接口明确返回 HTTP 404，且服务端消息准确对应当前请求的 `Route POST:<path> not found`，错误码缺省或为 `FST_ERR_NOT_FOUND`，才尝试一次无类型段路径。上游内容 404、其他路径缺失、401、500、网络失败均原样报告，不跳过初始化，也不静默切换目录。
