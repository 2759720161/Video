# 多源图片适配

项目目标是多源适配。目录接口形式、筛选参数名称和图片请求要求是相互独立的协议能力，不能用“新源／旧源”区分，也不能假定某一种订阅包代表全部来源。

## 本次日志

2026-10-23 20:58:44，目录 init、home 和 category 均返回 200。20:58:45 起，豆瓣图片 CDN 的封面 GET 大量返回 418；日志中的 `RespCode:418` 共 66 条。这些条目包含取色和原生图片组件的请求，并不代表 66 张不同图片。

另一个订阅中经图片代理加载的图片返回 200。电脑端对同一张豆瓣封面做对照：不附加请求头返回 418；附加 `Referer: https://movie.douban.com/` 和浏览器 User-Agent 后返回 200、17,506 字节有效 WebP。问题发生在图片请求，不能将其归因于分类解析或根据这个响应判定源失效。

## 处理方式

- 完整 Node 猫源共用 `CatArtwork` 地址适配。普通直链保持原样，协议相对地址补齐 HTTPS，来源提供的 `js2p://_WEB_`／相对图片代理路径继续走来源自身服务。
- 公开图片域名规则独立于目录名称和来源 key。目前对已验证需要 Referer 的 `img*.doubanio.com` 规则启用应用宿主图片桥接，在服务器请求图片时附加所需公开请求头。其他域名不套用豆瓣请求头。
- 桥接使用当前猫源运行环境的同一个本地端口，因此现有轮播、列表、详情和背景取色共用图片地址，无需分别修改页面样式。
- 桥接最多四个并发下载，相同 URL 合并请求；成功图片最多缓存 32 项、总计 8 MiB、有效期一小时，单张上限 5 MiB。请求总超时 12 秒，退出运行环境时终止下载并释放缓存。
- 仅接受明确匹配的公开图片域名、HTTP/HTTPS 默认端口及无用户密码的 URL；重定向重新检查规则，最多三次。非图片、空响应、错误状态和超限响应不作为成功图片缓存。没有关闭 TLS 校验、替换图片 CDN 或引入第三方镜像。
- 已缓存的 Node 目录图片若仍是受保护域名直链，恢复首页时会触发现有图片准备流程，并重建为当前运行端口的桥接地址；已是来源图片代理的地址只更新端口，不再包装。原生采集接口的缓存不因此启动 Node 订阅。

这是一项图片域名能力规则，不是“某个新源专用”的页面特判；也不意味着未知来源的一切图片鉴权方式已自动支持。需要其他请求头或其他鉴权协议时，应按真实协议增加独立能力规则，保留已支持的路径。

## 验证

已通过修改后的实际客户端、项目宿主和同一份校验后的 LeeCatPaw 脚本，读取 30 部作品并成功下载封面，状态 200、类型 image/webp、17,506 字节，文件签名包含 RIFF／WEBP。

脚本在文件读写仅允许临时目录的 Node 子进程中运行。桌面 Permission Model 禁止 fsync，因此测试子进程仅跳过该 flush；应用没有包含此替换。没有把远端猫源脚本重新内置进应用，也没有自动安装或调试设备；手机端显示仍需用户验证。

同时更正了接口和参数兼容文档，以及代码注释、测试名称中的源版本分类。带类型段／无类型段、filters／extend 各自继续兼容，作品和播放记录标识保持原样。
