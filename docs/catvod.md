# 猫源第一阶段

本阶段将原猫源包里的“天堂采集”以原生 ArkTS 方式接入，同时支持相同 JSON 采集协议的自定义地址。包含分类、搜索、分页、作品详情、线路和分集、现有播放器及继续观看。

使用入口：**服务 → 添加服务 → 猫源 → 测试并保存**。保存后可以打开该服务，或在首页菜单切换到它。添加服务不会自动改变当前首页选择。

默认来源地址来自原包：`http://caiji.dyttzyapi.com/api.php/provide/vod/`。源程序 `index.js` 和 `index.js.md5` 不能填入采集地址。本阶段没有内嵌 Node.js，也没有实现网盘登录、转存、网页嗅探或原包的全部代理。

## 数据与播放

- `CatVodClient` 请求分类、搜索分页及详情；请求具有时间、响应大小限制，并释放原生 HTTP 任务。
- `CatVodCodec` 解析 `vod_*`、`$$$`、`#` 和第一个 `$` 分隔符，保留 URL 中后续的 `$`。空值、重复作品、非 HTTP 标识及明确的 HTML 播放页不会被当成可播放分集。
- 播放身份由作品 ID、分集名称、同名分集出现次数构成，播放地址在开始播放时重新请求。线路按名称和同名出现次数对齐，避免按数组位置切错集。来源改变分集名称时，旧历史可能无法恢复。
- 默认优先名称含 `m3u8` 的线路，与原包天堂采集策略一致。显式选线缺少当前分集时返回错误，不自动换成另一集。
- Provider 复用现有播放会话、队列、线路选择及播放历史上报器。User-Agent 和可选 Referer 通过现有播放选项传递。

## 验证边界

新增测试覆盖协议异常、稳定身份、线路乱序、缺集、播放地址刷新、队列范围、HTTP 参数和错误处理。测试运行：`node scripts/test-catvod.mjs`，需要 Node.js 24 的类型剥离能力。网络与历史存储边界在主机测试中替换；原生 API 和 UI 由 HarmonyOS 构建检查，实际播放仍需真机验证。

来源可用性由上游决定。评估时分类及单条详情曾返回成功，所选 M3U8 清单返回 403；这不能被视为播放已验证。本实现不将服务端拒绝、网页响应或错误数据伪装为空列表成功。保存时的连接检查验证分类接口，不代表每个视频都可播放。

2026-10-14 验证记录：默认产品的调试 HAP 构建通过；猫源 14 项、首页来源 13 项、首页空状态 7 项、原搜索页 8 项、服务添加／目录创建 15 项、Toast 选项 1 项测试通过。目录创建测试夹具补充了已有 Toast 构造函数的替身，并新增猫源入口路由验证。

旧播放模型及详情测试共 25 项，其中 4 项失败。将其全部 23 个源码依赖复制到隔离目录，确认没有猫源或本次修改文件后，复现了相同失败：会话默认值、画中画更新断言、本地历史标识和临时文件标识。这些问题未在本阶段修改。真机 UI、起播及上游可用性尚未验证。
