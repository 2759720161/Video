# 搜索页转场与自动搜索

2026-10-23 修正。

## 日志与原因

log.txt 更新时间为 2026-10-23 22:10:44。日志记录了两次相同导航序列：

- 22:10:35.509 push 详情页；35.523 开始入场动画；35.546 replace 搜索页，距动画开始仅 23 毫秒。
- 22:10:38.892 push 详情页；38.907 开始入场动画；38.925 replace 搜索页，距动画开始仅 18 毫秒。

这说明部分缓存卡片仍通过详情页兜底识别推荐目录，在详情入场期间触发了二次导航。日志只记录了来源配置和初始化请求，没有 MediaSearch 的 seed_dispatch 或搜索请求。

日志同时出现输入框零增删更新。日志未暴露回调文字，不能单凭它确定自动搜索被取消的具体时刻；检查实际代码可以复现：editQuery 在比较文字是否变化之前就取消了待提交任务，同值回调也会丢失自动搜索。此前测试错误地把同值回调视为主动编辑，本次已修正该测试预期。

此外，原方案把业务提交绑定于页面动画进度和后续帧，替换路由或静止页面没有对应回调时可能等待。现已移除这些业务依赖。搜索页的自定义短距离位移/淡入也已移除，沿用与首页、详情页一致的系统路由动画，避免两端时长与运动范围不一致。

## 当前实现

首页卡片有明确搜索意图时直接导航搜索页。缺少意图的 CatNode 卡片先从本地运行宿主取得当前目录能力；确认 indexOnly 后直接进入搜索页，只发起一次导航。普通详情继续进入详情页，目录能力读取失败保留详情兜底。重复点击、切换来源/目录、隐藏和销毁均有检查，导航失败可重新点击。

搜索页在可见、初始化和范围恢复完成、会话可用时，通过零延迟任务提交一次带入的关键词，不再等待动画或渲染帧。任务执行前再次校验页面、初始化代次及关键词。隐藏或销毁撤销任务；恢复显示仅继续尚未提交的关键词；初始化重试使旧任务失效。

输入框回传相同文字时保留待提交状态。真正编辑和主动提交会取消排队任务，避免重复搜索。已有单目录/聚合范围照常生效，不扩大范围，不自动播放结果。

新增日志仅包含就绪状态、字符数、模式与范围数量，不记录搜索文字：seed_visible、seed_ready、seed_cancel reason=edited、seed_dispatch；首页记录 detail_route search=0/1。

## 验证

255 项相关测试通过，其中搜索页 60 项，轮播/首页 16 项。覆盖无转场/帧回调仍可提交、同值回调、设置恢复先后、隐藏、销毁、重试、实际编辑、主动提交，以及缓存缺少意图时直接导航、普通详情、能力读取失败、快速重复点击和过期回调。

应用完成编译和签名；产物校验 ZIP、签名配置、原生库及宿主资源。本次没有自动安装或调试设备，设备实际视觉效果和新日志尚未实测。
