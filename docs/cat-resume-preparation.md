## 已确认的瓶颈

现有 22:40 播放日志中，读取「盘」玩偶“空枪”详情耗时 16191 毫秒，播放地址解析耗时 2068 毫秒，合计准备耗时 18268 毫秒。该样本是从详情进入播放，不是新的历史卡片点击，不能据此宣称续播已实测提速至某个秒数。

继续播放代码同样先恢复分集，再解析播放地址。此前创建的来源实例没有跨实例的详情复用；进入播放器后还会刷新选集队列。这些请求可能重复访问同一作品详情。

## 详情复用

CatNodeProvider 显式启用 CatPlaybackPreparationCache。其他采集来源默认仍沿用实时详情与原有一次性历史详情交接，避免把包含临时直链的采集详情当作长效数据。没有按来源名称、目录名称或源的新旧设置分支。

缓存仅在进程内保存详情快照，不持久化到磁盘，不缓存最终 PlaybackStream 或其请求头。有效期为成功读取后两分钟，不因命中而续期。键包含来源 ID、类型、配置内容、更新时间及作品 ID；Node 运行地址对象是额外作用域，即使端口相同，新运行会话也不能命中旧快照。

相同键/作用域的并发读取合并为一个请求，每个读者取得独立副本，避免不同播放器、详情页或队列操作修改共享对象。缓存最多 24 条、总计 2Mi 字符；单条可使用总容量上限，不再以 256Ki 字符排除较长的详情。超额按 LRU 淘汰。空响应、错误、身份不符或没有标题的结果不保存。系统时钟回拨会使快照失效。

运行库停止/失败、配置中心修改请求及修改后离页都会清空缓存与在途登记；迟到响应不能重新填入已经失效的缓存。来源配置与版本变化通过键隔离。详情页明确重试绕过缓存，强制刷新也不允许旧在途结果覆盖新快照。

使用缓存详情后，如果线路中已找不到这一集，或播放解析明确报告资源/文件过期、404/410 等失效信息，仅强制重读详情一次。HTTP 500、一般登录错误不触发额外的慢详情请求，避免把来源故障扩大成重复等待。最终网盘播放地址每次仍由来源实时解析。

## 线路与队列

同一进程内记录最近一次成功解析的线路，按来源配置和分集身份隔离，有效期 30 分钟，最多 64 项。历史卡片重新打开时优先选择仍包含该分集的记录线路；不存在时沿用现有可用线路选择规则。该记录不是永久保存，也不表示对应媒体流已经成功出画面。

启动器直接从 Provider 已返回的完整线路分组构建初始队列，并保留所选分集最新的续播位置、线路与轨道设置。播放器有完整分组时不再立即重复读取详情；Emby、本地等没有这类分组的来源继续使用原队列刷新流程。来源身份、分集身份和取消导航保护保持生效。

新增诊断为 CatPlaybackPrepare 的 detail_prepare status=hit/miss/joined/refresh/retry_fresh，及 ProviderPlaybackLaunch 的 provider/item/resolve/history 分阶段耗时。不记录配置键、播放地址、凭据或作品 ID。

随后使用此前取得的实际“空枪”详情响应，在来源详情 HTTP 边界回放，实际 CatNodeProvider、CatNodeClient 和解析器继续执行。replay-review.json 记录：首次读取详情一次；新 Provider 恢复历史分集和刷新队列没有新增详情请求，得到 3 个队列项；改换运行地址对象后重新请求详情。回放中记录的毫秒值不代表网络播放性能，不作为手机续播提速结论。

远端脚本仍受独立临时目录读写权限限制；桌面 fsync 差异只在临时测试进程跳过，应用没有此替换。数据库/上报边界由测试替身提供，没有实际播放。

## 2026-10-24：较大详情与初始化复用

最新 log.txt 中，历史续播准备耗时 15367 毫秒：初始化 5293 毫秒，第一次详情 4397 毫秒，第二次详情 5415 毫秒，播放解析 108 毫秒。两次详情响应均为 312033 字符，准备缓存连续 miss。响应字符数不是解析后快照长度，原日志不足以直接证明容量拒绝。因此本次既修复容量策略，也增加实际快照长度与拒绝原因日志。

原先单条 256Ki 字符的门槛改为共用 2Mi 字符预算。总容量、24 条 LRU、两分钟有效期、副本隔离、强制重试和运行会话隔离保持生效。超过总预算的单条详情仍正常返回给调用者，但不保存；日志明确记录 not_stored reason=size_limit 与实际字符数。另有 empty、identity_or_title、invalidated、load_failed 及 runtime_changed/expired 诊断，不记录作品身份、详情内容、凭据或播放地址。

CatNodeClient 将成功的初始化路由协商结果按运行地址对象、订阅 URL、目录 key、配置 api 和 ext 复用，跨客户端有效期两分钟，最多 64 项。同一作用域内并发初始化合并；失败不保存，后续正常重试。typed/untyped 协商后的真实路径随结果复用，不按目录名称建立特殊规则。缓存清空时递增修订号，已存在的客户端下次请求同样重新初始化，避免配置中心更新后继续使用旧路径和旧首页状态。运行失败/停止、配置变动仍沿用已有清空入口。受独立搜索取消控制的客户端不共享初始化任务，防止取消一个搜索影响另一条播放请求。

329 项相关回归通过。新增真实 CatNodeProvider + CatNodeClient + 解析器的流程测试，在来源 HTTP 边界注入含 12 集、超过 256Ki 字符的详情：首次读取、恢复历史及另一个 Provider 再次续播合计仅 1 次 init、1 次 detail；两次播放分别实时解析地址。运行对象变动后重新初始化和读取，配置清空后已有客户端也重新初始化。数据由测试构造，未访问实际网盘、未实际播放，不将本地毫秒值作为手机提速结论。测试同时覆盖初始化过期、时钟回拨、并发合并、失败重试、迟到任务与容量限制。

未改动播放器 UI、沉浸光感配置或分类 tab；本次集中处理播放前的重复网络准备。没有自动安装或调试设备。实际来源初始化/详情请求本身的耗时以及播放器首帧等待仍受来源、网络和解码器影响。

## 2026-10-24：跨重启续播与空地址恢复

00:21—00:22 新日志证明较大详情缓存已生效：330975 字符快照成功保存，后续 resolve 命中。首次进程启动后的续播准备耗时 18341 毫秒，其中来源准备约 3214 毫秒、init 2224 毫秒、detail 3208 毫秒、play 9636 毫秒；最后 play 返回 HTTP 500、消息“夸克播放地址为空”。再次点击时详情和 init 均命中，play 仍在 8489 毫秒后返回相同错误。第三个请求读取不同大小的详情后成功，不能据此认定前两个请求的同一作品已经恢复。

新增 CatPlaybackSnapshotStore。每个订阅私有目录存储一个原子替换的 playback-metadata.json，最多 6 个作品、总计 2Mi 字符，详情有效期 30 分钟。键由来源配置/版本/作品身份、已校验的脚本 SHA256 和 profile.json 内容共同计算 SHA256；配置或登录资料改变、脚本更新、作品身份不符、时钟回拨、过期、文件损坏均不能命中。只保存详情输入与线路偏好，不保存解析得到的 PlaybackStream、请求头、原生 init 状态。原生服务重启后仍正常 init，最终媒体地址每次实时解析。

包含当前运行期 localhost、127.*、IPv6 loopback 或 js2p 的分集地址不写入持久缓存。豆瓣图片代理还原成原始图片 URL，重新打开时绑定当前代理端口；其他运行期封面地址不落盘。成功解析后记录的线路偏好不会延长详情有效期，也不会用旧的内存详情覆盖已经更新的磁盘详情。持久化故障只使缓存失效，不阻止正常网络读取。配置中心修改同时清空内存和当前订阅的持久缓存；在途旧结果有修订号保护，运行地址变化后的旧结果不能写入当前版本的快照。

内存缓存保留 disk_hit 来源标记，包括并发合并和后续内存命中。使用磁盘快照后遇到空播放地址或已有失效错误时，最多强制重新读取详情一次，并实时解析。普通网络新详情的 HTTP 500 不触发盲目的反复重读。

仅历史卡片启动允许备用线路恢复：来源明确表示播放地址为空时，最多尝试另一个包含完全相同分集名称和重复序号的线路。手动选择线路、选集面板切换默认不允许自动换线；登录失败、普通 HTTP 500/403 也不触发此恢复。存在磁盘过期标识时先完成一次强制详情刷新，再按同样规则处理；没有扫描全部线路或无限重试。成功后队列、当前线路和续播点都采用实际解析结果。来源全部线路没有有效地址时仍返回错误，不能将恢复机制解释成来源、账号或分享本身已经修复。

新增诊断 detail_prepare status=disk_hit、detail_snapshot stored=...、playback_recovery action=alternate_variant/result=...。未增加明文凭据或媒体地址日志。

337 项相关回归通过，包含真实 Provider/Client/解析器在模拟新进程作用域后不再重复 detail、仍重新 init、保留上次解析成功线路，profile/脚本变化隔离，旧 opaque 分集标识空地址后仅刷新一次，以及文件损坏、原子短写、过期不续期、预算、迟到写入和一次备用线路边界。网络边界使用构造响应，未实际访问用户账号或网盘。构建、签名和安装包完整性检查通过；没有自动安装或调试设备，没有实测手机首帧耗时。

## 2026-10-24：冷启动先恢复运行状态与首页预热

01:03 日志中磁盘详情缓存命中，恢复条目仅 93 毫秒，但播放准备总计 22746 毫秒：创建来源约 3384 毫秒、init 2143 毫秒、首次 play 9257 毫秒后报空地址、自动 detail 5800 毫秒、再次 play 1852 毫秒成功。该样本没有备用线路切换。它证实了“磁盘标识直接尝试、失败再重读”的恢复路径仍有一次昂贵失败；无法单凭日志区分标识过期和来源内部状态依赖。

对非 HTTP 的不透明分集标识采取保守准备策略：新运行会话首次播放该作品前，必须成功调用一次当前来源 detail。持久化元数据仍用于恢复作品展示和线路偏好，但不能充当来源已建立运行状态的证明。HTTP 形式的输入保留原缓存直续路径；如果曾观察到磁盘直续空地址、重读 detail 后同一线路解析成功，则在该作品的有效快照中记录 requiresLive，下一次冷启动同样提前准备。备用线路成功不会误标为“同线路恢复”。没有按源的新旧、目录名或夸克名称建立条件分支。

CatPlaybackPreparationCache 新增 requireLive 读取意图和运行地址隔离的准备登记。requireLive 不接受仅来自磁盘的快照；已有磁盘读取完成后可升级为一次真实详情请求，已有网络准备则直接合并。新鲜网络详情可跨 Provider 使用，最多记录 64 个作品准备状态；配置清空和运行地址变化使登记失效。正常热续播不重复准备，不持久化原生 init 或 runtime ready 状态。

首页恢复继续播放列表并显示后，仅在猫源首页活跃时，异步预热最近一条记录。prepareResume 只读取元数据、初始化来源和必要的 detail，不请求 play、不生成媒体直链、不创建播放器或页面导航。用户点击时可加入同一个在途准备；切换到服务/设置、离开页面、开始点击播放或来源版本变化后，守卫阻止该预热继续派发后续阶段。已经派发的共享请求不会因另一个读者离开而被终止。失败静默处理并允许后续重试，不覆盖首页作品、海报、轮播状态或显示错误 Toast。只预热一条，避免扫描全部历史。

343 项相关回归通过。新的实际 Provider/Client/解析器模拟来源在新作用域中若未执行 detail 就会返回空地址：磁盘展示恢复后，预热与另一个 Provider 的点击合并为一次当前会话 detail，首次且唯一一次 play 成功，无失败 play；同会话再次打开不重复 detail。另一个测试证明 HTTP 输入仍能直接使用磁盘详情，并在真实恢复条件发生后记住下次准备。另有磁盘在途读取升级、并发合并、运行地址/配置隔离、准备容量、依赖标记不延长有效期、首页只预热最近一条、失活守卫与静默失败重试。

这些是构造网络边界的正确性验证，不能当作新版手机耗时实测。运行库启动、来源 init/detail/play 及媒体解码自身的时间仍然存在；本次改变准备顺序、提前启动并消除可避免的先失败再重读。没有自动安装或调试设备。
