# LeeCatPaw 豆瓣分类筛选参数兼容

2026-10-23，最新 `log.txt` 中，20:48:24 的目录初始化和首页均返回 HTTP 200，随后分类接口返回 HTTP 500：

`Cannot read properties of undefined (reading 'u')`

这次已经不是接口路径缺失问题。LeeCatPaw 的豆瓣分类处理函数读取 `request.body.filters`，并直接访问 `filters.u`；项目原先只传递 `extend: {}`，导致 `filters` 为 undefined，在访问豆瓣远端接口前就抛出异常。

项目的完整猫源客户端现同时发送 `filters: {}` 和 `extend: {}`，保留 `filter: true`、分类 ID 和分页参数。这是对不同参数协议的兼容，不按“新源／旧源”分类，也不将其中一种协议视为替代另一种。空筛选对象使来源使用自己的默认值；例如豆瓣热播使用 `movie/hot_gaia`。不新增筛选 UI，不修改普通采集源客户端，不修改已保存的来源和播放记录，也不改写或内置远端脚本。
